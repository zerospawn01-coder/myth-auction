## M49自動preflight

`tests/m49_device_ux_preflight_test.gd`は、人間の理解度を代替せず、実機セッション前の操作不能だけを検査する。

- viewportが480 × 854である
- 6画面がそれぞれ独立したpage-level ScrollContainerを持つ
- 横スクロールを要求しない
- Claim／Warrantが境界折返しされる
- 主要操作領域が44px以上ある
- 未保存のClaim／Warrant／出品草稿が、画面移動やState更新で消えない
- Evidence選択が再描画で解除されない
- 現在画面のEvidenceを、クリップボードUIを経由せずHypothesisへ直接接続できる

このtestの通過は「UX合格」を意味しない。概念識別、画面迷子、ソフトウェアキーボード、内蔵ItemListのスクロール競合は実機観察でのみ判定する。

2026-07-21時点でM40～M51は12件すべて通過し、ルート側headless suiteも `29 passed / 0 failed` を確認した。

セッション記録には `project_manuals/ma001_device_ux_session_sheet.md` を使用する。

## Projection UX v3実装

2026-07-21に、ドメイン状態とプレイヤー可視情報の間へProjection境界を追加した。

- 保存しない`HazardProjector v0.1`が、確定済み観察だけから`UNASSESSED / SIGNAL_DETECTED`を再生成
- 受領時危険情報と現在の危険評価を別表示
- 自由記述Claim、TruthProfile、CANON_FACTを危険表示の入力から除外
- 表示名欠落時はmachine IDを出さず「表示名未登録」へfail-closed
- Evidenceの検証状態と仮説関係を独立バッジ化
- `□ / ☑`、一覧件数、スクロール継続表示を追加
- Clipboard entryへ`kind_id`を追加し、折り畳み時に種類別内訳を表示
- 通常CTAの金枠を外し、金色を推奨操作専用に限定
- 案件進捗を案件カードへ、Gold・Traceを上部資源バーへ分離

M50はHazard Projectionの純粋関数契約、M51はUI投影・machine ID非露出・Evidence二軸表示を検証する。通常Windows/OpenGL3による基準画像とSHA-256 manifestは`project_manuals/baselines/ma001_mvp_projection_v3_2026_07/`に保存した。

## 最優先で観察する4点

1. Evidence（観測・入手した事実）、Hypothesis（未確定の説明）、Claim（外部へ提出する主張）を、説明を読み返さず区別できるか。
2. 6画面の現在位置と、次に戻るべき画面を見失わないか。
3. クリップボードが比較・再利用の補助になり、全操作の必須運搬経路になっていないか。
4. 研究保留・返却・条件付き出品を「失敗」ではなく正規の判断として理解できるか。

## 30分セッション課題

テスターへ完成手順は示さず、次の目的だけを一つずつ渡す。

| 時間 | 課題 | 成功観察 |
| --- | --- | --- |
| 0–5分 | 品物を受領し、危険を断定せず最初の事実を一つ得る | 受領と真正性承認を混同しない |
| 5–12分 | 「過去所有者の記憶を保持」仮説へ根拠を二つ接続する | Evidenceと仮説の役割を言葉で説明できる |
| 12–18分 | 最初の説明と衝突するEvidenceを見つけ、次の調査を決める | 矛盾を失敗ではなく調査起点として扱う |
| 18–24分 | 委託するか自力継続するかを選び、理由を述べる | 人脈を工程能力として理解する |
| 24–30分 | Claimを作り、売却・保留・返却のどれかを選ぶ | 結末ではなく履歴に基づき判断を説明できる |

## 計測項目

- 各画面へ初めて移るまでの時間と誤タップ数
- Evidence／Hypothesis／Claimを取り違えた回数
- クリップボードを開いた回数、そこから実行した作業、不要な往復回数
- 「次に何をすべきか」と質問した地点
- 研究保留後に自発的に観察または資料検索へ戻れたか
- 最終判断の説明に参照したEvidence IDまたはカード数

合格目安は、操作説明なしで主要3概念を区別でき、画面迷子が2回以下、最終判断を2件以上の履歴へ結び付けて説明できることとする。

## 基準画像から既に見える残存リスク

- 数字タブは6工程を収められるが、工程名との対応を初見で記憶できるかは実機観察が必要。
- 研究ボードと出品審査はEvidence件数増加時の情報密度が高く、一覧から詳細へ移る操作はまだ弱い。
- Evidenceの二軸バッジは読めるようになったが、カード形状ではなく一行ItemListのため、状態比較の速度は未検証。
- 出品審査のClaim／Warrant入力欄は長文時の横スクロールを避けるため、境界折返しを有効にする。
- 人脈・委託画面は価格、監査措置、報告、異常判断が一画面に集まり、委託先が「人物」より設定フォームに見えやすい。

## 実機テスト中に変更しないもの

テスター間の比較を保つため、初回5セッションでは画面順、案件データ、初期資金、審査条件を変更しない。致命的な操作不能だけを即修正し、用語・色・カード形状・クリップボード挙動は観察結果をまとめてから一括比較する。
