# Contact Emblem Slice — Godot Implementation Contract

## 1. Scope & Hardened Boundary

This document defines the production implementation contract for the Contact Emblem projection within the MA-001 / MA-002 case package architecture.

The emblem is a pure runtime UI presentation derived deterministically from:
1. `contractor.emblem` (stable shape, symbol, palette, organization mark, and structural `risk_tier`).
2. `relationships[contractor.relationship_id]` (multi-dimensional relation state and runtime posture).

The key design rule is that relation state is compositional and not exclusive. A contact may simultaneously be trusted, indebted, monitored, secret-shared, and partially hostile.

---

## 2. Canonical Data Model

### 2.1 Package Schema Addition: `contractors[i].emblem`

Inside `case_package_v2`, each contractor record in `$.contractors[]` carries a machine-readable `emblem` definition. UI presentation strings (such as Japanese capability descriptions) MUST NOT be parsed to infer emblems.

```json
{
  "contractors": [
    {
      "id": "contractor_archivist",
      "category": "researcher",
      "relationship_id": "relation_archivist",
      "emblem": {
        "base_shape_id": "shape_research",
        "primary_symbol_id": "symbol_archive",
        "palette_id": "palette_civic",
        "organization_mark_id": "mark_public",
        "risk_tier": "low"
      }
    }
  ]
}
```

### 2.2 Relationship Resolution & Source of Truth

Contractors reference their relationship state via `contractor.relationship_id`:

```text
contractor.relationship_id → relationships[relationship_id]
```

Canonical relationship record:
```json
{
  "relationships": {
    "relation_archivist": {
      "contact_stage": "CONTACTED",
      "trust_tier": "HIGH",
      "relation_flags": ["TRANSACTED", "SECRET_SHARED", "MONITORED"],
      "relation_revision": 3
    }
  }
}
```

The runtime relationship state MUST remain multi-dimensional. A single enum such as `status` is insufficient.

The fields `disclosure_level`, `shared_secret_ids`, and `surveillance_state` are NOT canonical persisted fields. They are derived runtime posture signals and MUST NOT be duplicated as parallel saved state.

---

## 3. Pure-Function Projector Interface

`ContactProjector` is a pure function transformation layer. It takes only the contractor record and relationship record, producing an ephemeral `EmblemPresentation` dictionary.

```gdscript
class_name ContactProjector
extends RefCounted

static func project(contractor: Dictionary, relationship: Dictionary, rules: Dictionary = {}) -> Dictionary:
    # Pure-function derivation without global mutations or case_package dependencies
```

### 3.1 Input Contract

- `contractor`: `Dictionary` containing `id` (String), `category` (String), `relationship_id` (String), and `emblem` (Dictionary with `base_shape_id`, `primary_symbol_id`, `palette_id`, `organization_mark_id`, `risk_tier`).
- `relationship`: `Dictionary` containing `contact_stage` (String: `"UNKNOWN" | "RUMORED" | "CONTACTED" | "VERIFIED"`), `trust_tier` (String: `"LOW" | "MEDIUM" | "HIGH"`), `relation_flags` (Array of Strings), and `relation_revision` (int).
- `rules`: Optional rule/threshold overrides for badge placement, trust rim, hostility overlay, and secrecy seal rendering.

### 3.2 Output Contract (`EmblemPresentation`)

```json
{
  "contractor_id": "contractor_archivist",
  "relationship_id": "relation_archivist",
  "base_asset_id": "emblem_base_shape_research",
  "palette_id": "palette_civic",
  "symbol_asset_id": "emblem_symbol_archive",
  "mark_asset_id": "emblem_mark_public",
  "reveal_mask": "partial",
  "risk_perimeter": "unknown",
  "trust_rim": "high",
  "relation_badges": ["MONITORED", "SECRET_SHARED"],
  "hostility_overlay": null,
  "secrecy_seal": true,
  "interaction_overlay": null,
  "risk_tier": "low"
}
```

The presentation is not a stored canonical record. It is a projection generated by `ContactProjector` every time the UI renders.

Asset IDs adhere strictly to single-prefix rules:
- `base_shape_id: "shape_research"` $\rightarrow$ `base_asset_id: "emblem_base_shape_research"`
- `primary_symbol_id: "symbol_archive"` $\rightarrow$ `symbol_asset_id: "emblem_symbol_archive"`
- `organization_mark_id: "mark_public"` $\rightarrow$ `mark_asset_id: "emblem_mark_public"`

If `emblem` or `risk_tier` is omitted/missing, `risk_tier` defaults to `"unknown"`, and `base_shape_id` defaults to `"shape_generic"`.

## 4. Separation of Risk and Trust

Structural Risk (`risk_tier`) and Relationship Posture (`contact_stage`, `trust_tier`, `relation_flags`, `relation_revision`) ARE ENTIRELY SEPARATE DIMENSIONS.

- `risk_tier`: Inherited strictly from `contractor.emblem.risk_tier` (or category default if omitted). Relationship posture MUST NOT mutate `risk_tier`.
- Overlays: Derived dynamically from relationship posture and reveal state.

### 4.1 Relationship Overlay Matrix

| Dimension | Condition | Applied Layer |
| :--- | :--- | :--- |
| **Trust** | `trust_tier == "HIGH"` | `trust_rim` |
| **Trust** | `trust_tier == "LOW"` | `crack_overlay` |
| **Relation Flag** | `MONITORED` | `badge_top_right` |
| **Relation Flag** | `IN_DEBT` | `badge_bottom_left` |
| **Relation Flag** | `SECRET_SHARED` | `secrecy_seal` |
| **Relation Flag** | `HOSTILE` | `hostility_overlay` |
| **Relation Flag** | `AUTHORIZED_PROXY` | `badge_top_left` |
| **Relation Flag** | `MUTUAL_DEPENDENCE` | `badge_bottom_center` |

This matrix intentionally allows multiple flags to coexist at once.

## 5. Reveal & Layering Model

Reveal state is not a single `reveal_tier`. It is split into independent channels:

```json
{
  "reveal": {
    "identity_reveal": "ALIAS_ONLY",
    "role_reveal": "CONFIRMED",
    "specialty_reveal": "PARTIAL",
    "hazard_reveal": "SIGNAL_DETECTED",
    "portrait_reveal": "HIDDEN",
    "background_reveal": "HIDDEN"
  }
}
```

This supports the requirement that identity, role, specialty, and hazard can be disclosed at different speeds.

### 5.1 Layer Composition Order

The compositor MUST use a fixed z-order:

1. Base shape
2. Specialty glyph
3. Reveal mask
4. Risk perimeter
5. Trust rim
6. Relation badges
7. Hostility overlay
8. Secrecy seal
9. Interaction overlay

### 5.2 MVP Scope

The initial MVP MUST implement:
- 6 to 8 handcrafted emblem variants
- base shape
- specialty glyph
- risk perimeter with `UNKNOWN / SIGNAL / ASSESSED`
- trust rim
- relation badges for debt, monitoring, secrecy, hostility
- independent reveal channels for identity and hazard

The MVP MUST NOT implement:
- contact claim assertions
- support ceiling logic
- auto-generated hazard questionnaires
- large-scale auto-generated emblem synthesis
- portrait rendering

## 6. Cross-cutting Engine Constraints

決定論的予約、汎用Participant、Predicate能力解決、View/Domain State分離、
TraceとProjectionの責務分離については、
[MYTH AUCTION 汎用Research Case実装契約 v0.1](myth_auction_generic_research_case_contract_v0_1.md#myth-auction-補正決定論マルチ対象行動生成)
を唯一の正本とする。本書では同じ定義を複製しない。

Contact Emblem固有の帰結は次のとおり。

- `EmblemPresentation`は保存せず、検証済みDomain Stateから再生成する。
- 関係・危険・開示の表示は`ActionGate`や`ActionAvailabilityProjection`の代替判定にならない。
- Ledger完全性が失われた場合、Contact projectionもfail-closed表示へ落とす。
- UIが保持できるのは選択、展開、スクロール、アニメーション等の一時View Stateだけである。

## 7. Verification & Compliance Requirements

1. **Validator Integration**: `CasePackageValidator.validate_package(package)` validates `contractor.emblem` shape IDs fail-closed if present.
2. **Presenter Integration**: `ResearchCasePresenter` embeds `emblem_presentation` into presented contractor view models by resolving `contractor.relationship_id` against `state.relationships`.
3. **Headless Test Coverage**: `tests/m52_contact_projector_test.gd` verifies end-to-end package loading, presentation projection, layered composition, and fail-closed validation.
